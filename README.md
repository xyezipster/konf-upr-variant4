# Эмулятор оболочки, вариант 4

Практическая работа № 1 по дисциплине «Конфигурационное управление».
Группа ИКБО-62-25. Автор: [xyezipster](https://github.com/xyezipster).

Программа имитирует командную строку UNIX. Она загружает файловую
систему из JSON, выполняет команды над её копией в памяти и при
необходимости записывает журнал вызовов. Реализованы все пять этапов
варианта 4: REPL, настройки, VFS, основные команды и `chmod`.

## Запуск

Нужен Python 3.10 или новее. Программа использует стандартную
библиотеку, поэтому устанавливать пакеты и собирать проект не нужно.
Все команды ниже выполняются из папки проекта.

На macOS и Linux:

```sh
./run.sh
./run.sh --vfs data/demo.json --log logs/session.json
./run.sh --vfs data/demo.json --startup scripts/stage5.txt
```

На Windows:

```bat
run.bat --vfs data/demo.json --startup scripts/stage5.txt
python -B -m unittest discover -s tests -v
```

Прямой запуск, одинаковый для всех ОС:

```sh
python3 -B -m src --vfs data/demo.json
```

В Windows вместо `python3` обычно используется `python`.
Для выбора интерпретатора в `run.sh` предусмотрена переменная `PYTHON`:

```sh
PYTHON=/path/to/python3 ./run.sh
```

`run.sh` и `run.bat` отсчитывают относительные пути от папки проекта.
При прямом запуске Python пути отсчитываются от текущего каталога ОС.

## Настройки

| Параметр | Назначение | Если не указан |
| --- | --- | --- |
| `--vfs PATH` | JSON-файл виртуальной файловой системы | Пустой корень в памяти |
| `--log PATH` | JSON-журнал команд | Логирование отключено |
| `--startup PATH` | Стартовый скрипт UTF-8 | Сразу открывается REPL |
| `--help` | Справка о параметрах | Обычный запуск |

При запуске программа печатает значения всех трёх путей. Приглашение
содержит имя VFS и текущий виртуальный каталог, например `demo:/$ `.
Имя берётся из имени JSON-файла без расширения; без файла это `MyVFS`.
Если VFS не загрузилась, программа сообщает об ошибке и завершает
работу с кодом 1. Неверные параметры запуска дают код 2.

Путь журнала не должен совпадать с VFS или стартовым скриптом,
в том числе через символическую или жёсткую ссылку.
Родительские каталоги нового журнала программа создаёт сама.

## Ввод команд

Парсер раскрывает `$NAME` и `${NAME}` из окружения реальной ОС.
Неизвестная переменная даёт пустую строку. Пробелы внутри раскрытого
значения остаются в одном аргументе. Двойные кавычки сохраняют пробелы
и разрешают раскрытие; одиночные кавычки сохраняют буквальный текст.
Обратная косая черта вне одиночных кавычек экранирует следующий символ.

```text
ls "$HOME"
ls '${HOME}'
cd "/home/student/docs"
```

`$HOME` содержит путь реальной ОС, который может отсутствовать в VFS.
Тогда команда выдаёт «Путь не найден». Команды эмулятора не обращаются
к файлам реальной ОС по раскрытому пути.

`#` после пробела или в начале строки начинает комментарий.
Внутри кавычек и внутри слова символ `#` остаётся частью аргумента.
Пустые строки и комментарии программа пропускает. Конвейеры,
перенаправления, подстановка команд и маски `*` не реализованы.

## Команды

| Команда | Действие |
| --- | --- |
| `ls [-al] [пути...]` | Содержимое каталогов или имя заданного файла |
| `cd [путь]` | Смена каталога, без пути переход в `/` |
| `whoami` | Имя пользователя реальной ОС |
| `cal [год]` | Текущий месяц без аргументов или весь заданный год |
| `cal месяц год` | Календарь заданного месяца |
| `du [-s] [пути...]` | Размер файлов и каталогов в байтах |
| `chmod [-R] режим пути...` | Изменение прав узлов VFS в памяти |
| `exit` | Завершение эмулятора, аргументы запрещены |

`ls` сортирует имена. Флаг `-a` включает скрытые элементы,
`-l` показывает права и размер файла в байтах; флаги можно объединять.
В колонке размера каталог имеет 0: его собственное содержимое не
является файлом. Для нескольких путей программа выводит заголовки.
Без пути `ls` и `du` работают в текущем каталоге.

Пути бывают абсолютными и относительными. Поддерживаются `.` и `..`;
выход выше корня оставляет текущим каталогом `/`. Символ `~`
не раскрывается. `cd` принимает только существующий каталог.

`cal` начинает неделю с понедельника. Названия месяцев и дней
печатает стандартная библиотека Python. Год должен быть от 1 до 9999,
месяц от 1 до 12. Например, `cal 2 2024` показывает 29 февраля.

`du` считает длину содержимого файлов, включая двоичные и скрытые.
Размер каталога равен сумме размеров файлов во всём его поддереве.
Без `-s` выводятся также вложенные каталоги, с `-s` только итоги
заданных путей. Это логические байты, без учёта дисковых блоков ОС.

`chmod` принимает три восьмеричные цифры (`600`, `644`, `755`) или
символьные выражения с `u`, `g`, `o`, `a`, операциями `+`, `-`, `=`
и правами `r`, `w`, `x`. Несколько выражений разделяются запятыми.
Если группа не указана, меняются права всех групп, без учёта umask.
Флаг `-R` меняет также права потомков. Специальные биты и копирование
прав между группами не поддерживаются.

```text
chmod 600 /hello.txt
chmod u+x,g-r,o= /hello.txt
chmod -w /hello.txt
chmod a=rx /docs
chmod -R 700 /home
chmod 644 /hello.txt /docs/readme.txt
ls -l /hello.txt
```

Права хранятся как метаданные и отображаются через `ls -l`.
Эмулятор не проверяет их при чтении каталогов. Изменения пропадают
после завершения: при новом запуске права снова читаются из JSON.

Для `ls`, `du`, `chmod` маркер `--` завершает разбор флагов.
Неизвестная команда, неверные аргументы, незакрытые кавычки и
несуществующий путь вызывают сообщение об ошибке. REPL продолжает
работать. Если один из путей `chmod` неверен, права не меняются нигде.

## Формат VFS

JSON содержит объект с массивом `entries`. Вложенность задаётся
абсолютными путями: `/home/student/docs` находится внутри
`/home/student`. Родительские каталоги нужно перечислить явно.
Корневой каталог `/` обязателен, пути должны быть уникальными.

```json
{
  "entries": [
    {"path": "/", "type": "dir", "mode": "755"},
    {"path": "/docs", "type": "dir", "mode": "755"},
    {
      "path": "/docs/hello.txt",
      "type": "file",
      "mode": "644",
      "encoding": "base64",
      "data": "SGVsbG8hCg=="
    }
  ]
}
```

`type` равен `dir` или `file`. `mode` содержит три восьмеричные цифры;
если его нет, используются `755` для каталогов и `644` для файлов.
Файл требует `encoding: base64` и поле `data`. В примере закодирована
строка `Hello!` с переводом строки. Текст и двоичные данные хранятся
одинаково, после загрузки как байты в памяти.

Программа отклоняет неверный JSON, типы узлов, base64, права,
повторяющиеся пути и узлы без родительского каталога.
Исходный файл VFS программа только читает и никогда не перезаписывает.
Команд сохранения или распаковки VFS в этом варианте нет.

| Файл | Содержимое |
| --- | --- |
| `data/minimal.json` | Только корневой каталог |
| `data/files.json` | Текстовый и двоичный файлы |
| `data/deep.json` | Каталоги `/home/student/docs` и файл внутри |
| `data/demo.json` | Общий пример, включая скрытый файл |
| `data/invalid.json` | Неверный формат для проверки ошибки загрузки |

## Стартовый скрипт и журнал

Стартовый скрипт содержит одну команду на строку. Программа показывает
приглашение, исходную команду и результат, как при ручном вводе.
При ошибке печатает путь скрипта и номер строки, затем выполняет
следующие команды. Если файл нельзя прочитать, сообщает об этом
и открывает REPL. `exit` в скрипте завершает всё приложение.

```sh
./run.sh --vfs data/demo.json --log logs/session.json \
  --startup scripts/stage5.txt
```

Журнал содержит JSON-массив событий. Каждое событие имеет поля
`timestamp` (UTC), `user`, `command`, `output`, `status` (`ok` или
`error`) и `exit`. Программа записывает успешные и ошибочные вызовы,
включая `exit`; комментарии и пустые строки в журнал не попадают.
Существующий массив событий сохраняется и дополняется. Журнал
рассчитан на один процесс. Ошибка его чтения или записи завершает
приложение с кодом 1. Каталог `logs/` исключён через `.gitignore`.

## Проверка и примеры

```sh
python3 -B -m unittest discover -s tests -v
./scripts/demo_config.sh
./scripts/demo_errors.sh
./scripts/demo_vfs.sh
./scripts/demo_vfs_errors.sh
./scripts/demo_commands.sh
```

38 тестов проверяют парсер, настройки, журнал, стартовый скрипт,
загрузку VFS и все команды. Есть проверка неизменности исходного JSON
после `chmod`, а также запуск приложения отдельным процессом.

`demo_config.sh` проверяет параметры, `demo_errors.sh` ошибки скрипта,
`demo_vfs.sh` разные структуры VFS и запуск без файла,
`demo_vfs_errors.sh` отсутствующий файл и неверный JSON.
`demo_commands.sh` выполняет режимы основных команд и `chmod`.
В демонстрационных скриптах часть команд намеренно вызывает ошибки.

Пример интерактивного сеанса:

```text
demo:/$ ls
docs
hello.txt
home
demo:/$ cd /home/student/docs
demo:/home/student/docs$ ls
note.txt
demo:/home/student/docs$ cd
demo:/$ chmod 600 /hello.txt
demo:/$ ls -l /hello.txt
-rw-------      7 hello.txt
demo:/$ exit
```

## Этапы в истории Git

Каждый этап находится в своей ветке `stage-1` ... `stage-5`.
Ветки содержат накопленную версию: этап 3 включает этапы 1 и 2.
`main` содержит всю работу. Коммиты оформлены по Conventional
Commits, теги с теми же именами отмечают завершение этапов.
В ранних версиях `ls` и `cd` являются заглушками, как требует задание.

| Ветка | Содержание |
| --- | --- |
| `stage-1` | REPL, имя VFS, переменные окружения, заглушки и exit |
| `stage-2` | Параметры запуска, журнал с пользователем, стартовый скрипт |
| `stage-3` | JSON VFS, base64, пустой корень и ошибки загрузки |
| `stage-4` | Работающие ls и cd, команды whoami, cal, du |
| `stage-5` | chmod, проверки сохранности VFS и полная документация |

Посмотреть изменения этапа без переключения текущих файлов:

```sh
git log --oneline --reverse
git show refs/heads/stage-3
```

Материалы дисциплины: [true-grue/kisscm](https://github.com/true-grue/kisscm).
Индивидуальное задание: сборник ПР № 1 для ИКБО-62-25, вариант 4,
страницы 17–19. README описывает итоговую версию; ранние ветки содержат
описание возможностей соответствующего этапа.

Для переключения на отдельный этап:

```sh
git switch stage-1
./run.sh
git switch main
```
