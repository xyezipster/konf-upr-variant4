# Эмулятор оболочки, вариант 4

Практическая работа № 1 по конфигурационному управлению.
ИКБО-62-25. Автор: [xyezipster](https://github.com/xyezipster).

Консольный эмулятор UNIX-оболочки. Все операции с виртуальной
файловой системой (VFS) выполняются в памяти. Реализованы пять этапов.

## Запуск

Нужен Python 3.10+. Дополнительных библиотек и сборки нет.
Команды выполняются из папки проекта.

```sh
python3 -B -m src
```

Запуск с VFS, журналом и стартовым скриптом:

```sh
python3 -B -m src --vfs data/demo.json --log logs/session.json --startup scripts/stage5.txt
```

## Параметры

| Параметр | Назначение |
| --- | --- |
| `--vfs PATH` | Путь к VFS |
| `--log PATH` | JSON-журнал команд |
| `--startup PATH` | Стартовый скрипт UTF-8 |
| `--help` | Справка |

Все параметры необязательны и выводятся при запуске.
Стартовый скрипт выполняет команды по строкам и показывает ввод и вывод.
При ошибке сообщает номер строки и продолжает выполнение.
`exit` завершает программу. В журнал попадают вызовы команд,
результаты, ошибки, время и имя пользователя ОС.

Парсер поддерживает кавычки, `$NAME` и `${NAME}` из окружения ОС.
Одиночные кавычки запрещают раскрытие переменных. `#` в начале строки
или после пробела начинает комментарий. Ошибки выводятся в консоль.
Приглашение содержит имя VFS и текущий каталог.

## Команды

| Команда | Действие |
| --- | --- |
| `ls [-al] [пути...]` | Список файлов; `-a` включает скрытые, `-l` показывает права и размер |
| `cd [путь]` | Переход в каталог; без пути в `/` |
| `whoami` | Имя пользователя ОС |
| `cal [год]` | Текущий месяц или заданный год |
| `cal месяц год` | Заданный месяц |
| `du [-s] [пути...]` | Размер в байтах; `-s` выводит только итоги |
| `chmod [-R] режим пути...` | Изменение прав; `-R` также меняет права потомков |
| `exit` | Завершение программы |

Поддерживаются абсолютные и относительные пути, `.` и `..`.
`du` считает байты содержимого файлов, включая скрытые.
`chmod` принимает числовые права (`600`, `755`) и символьные
(`u+x`, `g-w`, `a=rx`). Права отображаются через `ls -l`, но не
ограничивают доступ внутри эмулятора. Изменения исчезают при выходе.
Конвейеры, перенаправления и маски файлов не поддерживаются.

Пример ручного ввода:

```text
ls -al
cd /home/student/docs
ls
cd /
whoami
cal 2 2024
du -s /
chmod 600 /hello.txt
ls -l /hello.txt
exit
```

## VFS

VFS загружается из JSON в память. Без `--vfs` создаётся пустой корень.
Вложенность задаётся абсолютными путями, родительские каталоги
перечисляются явно. Пример:

```json
{
  "entries": [
    {"path": "/", "type": "dir", "mode": "755"},
    {
      "path": "/hello.txt",
      "type": "file",
      "mode": "644",
      "encoding": "base64",
      "data": "SGVsbG8hCg=="
    }
  ]
}
```

Файлы хранятся в base64. Если `mode` не задан, каталог получает `755`,
файл `644`. Исходный JSON программа только читает.
В `data/` есть минимальная VFS, несколько файлов, три уровня
каталогов и файл с неверным форматом для проверки ошибок.

```sh
python3 -B -m unittest discover -s tests -v
```

38 тестов проверяют парсер, настройки, журнал, VFS и команды,

## Исходники

| Модуль | Назначение |
| --- | --- |
| `src/__main__.py` | `main` запускает программу, `repl` читает команды |
| `src/config.py` | `parse_config` читает параметры, `Config` хранит настройки |
| `src/parser.py` | `parse_command` разбирает строку и переменные |
| `src/shell.py` | `Shell.execute` и `dispatch` выполняют команды |
| `src/startup.py` | `run_startup` выполняет стартовый скрипт |
| `src/eventlog.py` | `EventLog` читает и дополняет JSON-журнал |
| `src/vfs.py` | `VFS.load`, `resolve`, `children` загружают VFS и обрабатывают пути |
| `src/commands.py` | Реализация команд оболочки |
| `src/modes.py` | `parse_changes` и `apply_changes` обрабатывают права chmod |

Остальные функции описаны в docstring в исходном коде.

## Этапы

| Ветка | Содержание |
| --- | --- |
| `stage-1` | REPL, парсер, заглушки ls и cd, exit |
| `stage-2` | Параметры, журнал, стартовый скрипт |
| `stage-3` | JSON VFS в памяти |
| `stage-4` | ls, cd, whoami, cal, du |
| `stage-5` | chmod и итоговая версия |

Каждая ветка включает предыдущие этапы. В `main` находится вся работа.
